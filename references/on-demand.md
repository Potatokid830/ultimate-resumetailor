# 按需生成：面试速查卡、网申纯文本、速成清单

用户说"要投了 / 要填网申 / 接到面试了 / 要速查卡 / 要速成清单"时再生成，存成和 docx 同名的 `<文件名>.notes.md` 放在同一目录（已有就追加），对话里也给出。所有内容只能来自这一版简历和 `materials.md`：不另加内容，不教用户夸大。文中"第 X 节"都指 SKILL.md 里的章节。

## 面试速查卡

用户接到面试或要求时生成；海投多个版本时，防止面试时记不清这一版写了什么。

- 版本信息：公司、岗位、投递日期、文件名、用的是哪个方向的写法
- 这一版写进去的每个数字，以及它在素材库里的依据（怎么算出来的）
- 每条带"判断 / 建议"的要点：当时是怎么分析出这个结论的，按素材库里的真实过程写，面试官追问"你怎么得出的"时照这个讲
- 每个"先写后学"技能：学到什么程度、练手项目做到哪了，以及 2–3 句实诚的回答（会什么、在哪用过、还在学什么），不教用户夸大
- 和这一份最容易混的其他版本差在哪（同一段经历在别的版本写成了什么角度）

## 网申纯文本

用户要填网申时生成；北森、Moka、各公司官网、Workday 等要一格一格填表时直接复制。

- 按网申表的常见字段排：教育（学校、学位、专业、起止年月、GPA 按第 1 节规则）、每段经历（公司、部门、职位、城市、开始年月、结束年月、描述）、项目、技能、证书
- 日期统一写 `YYYY-MM`（如 `2025-07`）；描述用"1. 2. 3."分行，**不用项目符号、粗体、箭头和表格**
- 内容和这一版简历一致，不另加内容；如果用户说表单有字数上限，另给一版压缩到上限以内的

## 速成清单（"先写后学"的技能）

每个"先写后学"的技能一份（规则见 SKILL.md 第 2 节），包括：

- 面试会问到什么程度
- 1–2 天的学习路线
- 一个能放进作品集的练手小项目
- 3–5 道可能被问到的面试题

最后提醒用户学完之后再投、再面。
